# ProjectMate 로컬 모델 실험 (Qwen3.5 4B LoRA)

ProjectMate의 'AI 변경안' 기능을 GPT 대신 작은 로컬 모델로 할 수 있는지 시험한 기록이다. 기간은 2026-11-14 ~ 2026-11-19이다. 제품 기능이 아닌 개인 실험이며, 이 브랜치에는 실험 파일만 있고 운영 코드는 없다.

**한 줄 결론:**
- 4B 모델을 파인튜닝하면 GPT 답과 70% 중반까지 일치하고, 사례당 약 1초에 답한다.
- 하지만 사전에 정한 합격 기준을 넘지 못했다. 새 업무 제목·담당자·마감 같은 세부 변경에도 약하다.

## 무엇을 시켰나

입력은 GitHub 이슈·PR 타임라인 원문과 프로젝트의 현재 업무 목록이다. 모델은 세 결정 중 하나를 고르고, 변경을 제안할 때는 바꿀 내용을 JSON으로 낸다.

| 결정 | 뜻 |
|---|---|
| `no_change` | 업무 목록을 바꿀 근거가 없다 |
| `propose_changes` | 완료·상태·담당자·마감 변경이나 새 업무를 제안한다 |
| `needs_clarification` | 사람에게 먼저 확인해야 한다 |

## 사용한 모델과 설정

| 항목 | 내용 |
|---|---|
| 기본 모델 | **Qwen3.5-4B** (`Qwen/Qwen3.5-4B`, Apache-2.0) |
| 모델 크기 결정 | 처음 계획은 9B였다. bf16 LoRA에 VRAM이 9B는 22GB, 4B는 10GB 필요하고, 장비는 12GB라 4B로 바꿨다 |
| 학습 방식 | bf16 LoRA r=16, lr 2e-4, 배치 1×8, 최대 3 epoch. 검증 손실이 가장 낮은 epoch를 시험 전에 고른다 |
| 학습 장비 | Windows 데스크톱 RTX 4070 12GB. 1000건 학습 한 번에 약 49분 |
| 서빙 | llama.cpp b12184. GGUF 4비트(Q4_K_M)와 8비트(Q8_0) 기본 모델에 LoRA 어댑터를 올린다. JSON 스키마 강제, temperature 0 |
| 학습 라벨 | GPT `gpt-5.6-sol` (reasoning low)의 응답을 정답으로 삼아 따라 하게 했다. 최대 1000건이다. 후반에 새로 받은 라벨 962건의 비용은 약 $10.65다 |
| 시험지 | 보류 A 253건. 학습 데이터와 사례·저장소가 겹치지 않는다 |
| 답안지 1 (GPT) | sol low의 응답이다. 'GPT만큼 답하는가'를 잰다 |
| 답안지 2 (Claude) | 실험 전에 고정한 Claude 블라인드 라벨이다. 사전 합격 기준은 이 답안지로 판정한다 |
| 비교한 GPT | sol low(기준), terra low, luna low. 앱 운영 모델(gpt-6.1-sol)과는 비교하지 않았다 |

**지표**
- **결정 일치:** 세 결정 중 같은 것을 고른 비율이다.
- **변경 F1:** 제안한 변경의 (종류, 대상 업무)가 답안지와 겹치는 정도다. 상태 변경은 바꾼 값도 본다.
- **S1:** 하면 안 되는 변경을 낸 사례 수다. 기준은 6건 이하다.
- **S2:** 없는 업무를 참조한 횟수다. 기준은 2건 이하다.

## 결과

### 단계별 성능 (GPT 답안지, 보류 A 253건)

| 단계 | 학습 데이터 | 결정 일치 | 변경 F1 |
|---|---|---:|---:|
| 파인튜닝 전 | 없음 | 45.5% | 37.1% |
| 첫 학습 | GPT 라벨 100건 | 68.0% | 52.0% |
| 데이터 늘리기 | 402건 | 73.1% | 55.8% |
| 어려운 사례 추가 | 797건 | 70.0% | 62.0% |
| 무작업 오답 추가, seed 3회 평균 | 849건 | 73.1% ± 2.1 | 64.7% ± 2.7 |
| 같은 어댑터를 8비트로 서빙, seed 3회 평균 | 849건 | 75.4% | 66.9% |
| seed 어댑터 3개 평균 (4비트, 1회 측정) | 849건 | 76.3% | 70.0% |
| 같은 분포 151건 추가, 4비트 seed 3회 평균 | 1000건 | 75.5% | 66.7% |
| 같은 분포 151건 추가, 8비트 seed 3회 평균 | 1000건 | 73.9% | 63.7% |
| (참고) GPT terra low | — | 73.9% | 62.4% |
| (참고) GPT luna low | — | 77.5% | 67.8% |

### 알게 된 것

1. **파인튜닝 효과는 확실했다.** 100건만으로 결정 일치가 +22.5%p 올랐다. 849건 모델은 GPT와의 차이 중 결정 일치 약 51%, 변경 F1 약 44%를 메웠다.
2. **데이터는 양보다 고르는 것이 중요했다.**
   - 같은 분포를 늘리면 효과가 빨리 줄었다. 849건에서 1000건으로 늘려도 seed 평균으로 차이가 없었다.
   - 모델이 약한 사례를 골라 넣었을 때 변경 F1이 학습 편차보다 크게 올랐다.
3. **학습 한 번의 결과는 4~5%p 흔들린다.** seed만 바꿔도 이만큼 달라서, 단계는 seed 3회 평균으로 비교했다.
4. **서빙 정밀도의 효과는 어댑터마다 달랐다.**
   - 849건 어댑터는 8비트에서 일관되게 올랐다.
   - 1000건 어댑터는 8비트에서 오르지 않았다.
5. **세부 변경이 약하다.**
   - 시험지에서 GPT가 낸 새 업무·담당자·마감 변경은 11개다. 로컬은 그중 1개만 종류와 대상이 맞았다.
   - 원문에 날짜가 있어도 마감으로 옮기지 못하는 경우가 있었다.
   - 근거 없는 담당자 변경도 냈다.
   - 지금 채점은 제목·담당자·마감을 보지 않아서 위 점수에는 이 약점이 드러나지 않는다.

### 사전 합격 기준 판정 (Claude 답안지, sol low 대비 마진 −6%p)

- **결정 일치(G1)와 변경 F1(G2):** 로컬 단독 설정은 모두 '판정 불가'이거나, 일부 seed의 G2가 '미달'이었다. 비열등을 보이지 못했다.
- **금지 변경(S1):** 대부분 기준(6건)을 넘었다. seed에 따라 4~19건이다.
- **없는 업무 참조(S2):** 모두 통과했다.
- 결론적으로 사전에 정한 "GPT에 비열등"이라는 결론은 쓸 수 없다.

### 혼합 방식: 로컬이 거르고 GPT가 쓴다 (저장된 결과로 계산)

로컬이 `no_change`라고 하면 GPT를 부르지 않는다. 그 밖의 경우에는 GPT 응답을 쓴다.

| Claude 답안지, 9개 변형 평균 | 결정 일치 | 변경 F1 | S1 | GPT 호출 |
|---|---:|---:|---:|---:|
| 로컬 단독 | 67.5% | 57.7% | 4~17 | 0% |
| 로컬 거르기 + GPT | 68.9% | 63.6% | **2~4** | 35~46% |
| GPT 단독 (sol low) | 72.7% | 67.0% | 4 | 100% |

- 금지 변경(S1)과 없는 업무 참조(S2)가 모든 변형에서 기준을 통과했다.
- GPT 호출은 절반 넘게 줄었다.
- 결정 일치는 GPT보다 약 4%p 낮다. 로컬이 무변경으로 걸러 버린 사례 안에 실제 변경 제안의 14~28%, 확인 필요의 절반 이상이 섞여 있기 때문이다.
- 저장된 GPT 응답을 다시 쓴 계산이라, GPT를 새로 부를 때의 응답 편차는 빠져 있다.

## 최종 결정

- **앱에는 로컬 모델을 넣지 않는다.** ProjectMate의 AI 변경안은 계속 GPT(gpt-6.1-sol)로 한다. 이유는 셋이다.
  - 사전 기준에서 비열등을 보이지 못했다.
  - 금지 변경이 대부분 기준을 넘었다.
  - 세부 변경 내용이 약하다.
- **가장 쓸모 있어 보이는 구조는 '로컬이 거르고 GPT가 쓰는' 혼합 방식이다.** 다만 실험 기록으로만 남기고 앱에 적용하지 않는다(2026-11-19 결정).
- **같은 분포의 데이터를 더 모으는 것은 멈춘다.** 849건 → 1000건에서 효과가 보이지 않았다.
- **서빙은 4비트와 8비트 중 어느 쪽도 일관되게 낫지 않았다.** 지연(약 1.0초 대 1.4초)과 파일 크기(2.7GB 대 4.6GB)만 보면 4비트가 낫다.

**다시 시작한다면 할 일**
- 혼합 방식에서 무변경 확률에 문턱을 두어 거르는 정확도를 높인다.
- 제목·담당자·마감까지 채점하는 시험 세트를 만든다.
- 보류 A를 여러 번 봤으므로 새 시험지로 다시 확인한다.
- 약한 '확인 필요' 유형의 데이터를 보강한다.
- 9B 모델을 시도한다. 클라우드 GPU가 필요하다.

## 파일 구성

| 경로 | 내용 |
|---|---|
| `REPORT.md` | 전체 실험 보고서. 사전 고정 기준, 단계별 수치, 해시, 명령 |
| `IMPROVEMENT.md` | 단계별 성능 변화 흐름 요약 |
| `SETUP-windows.md` | 데스크톱 학습·서빙 환경 준비 |
| `app-samples.md`, `app-inputs.json` | 앱 형식 표본 양식. 아직 채우지 않았다 |
| `train.py` | LoRA 학습 |
| `make_split.py` | 학습·검증 분할과 학습 데이터 생성 |
| `run.py` | 로컬 모델 평가 실행. GPT 평가 스크립트에 로컬 변형을 더했다 |
| `compare.py` | 보류 A 채점, 사전 기준 판정, 짝 부트스트랩 구간 |
| `pool.py` | seed 여러 개의 평균끼리 비교 |
| `hybrid.py` | 혼합 방식 계산 |
| `test_*.py` | 분할·평가 스크립트 테스트 |
| `results/local-*/` | 보류 A 253건에 대한 로컬 모델 응답, 변형 20개 |
| `evidence/` | 학습 로그, 비교 출력, 서버 확인 기록, 공개하지 않은 파일의 sha256 ([설명](evidence/README.md)) |

- 문서와 스크립트 안의 경로는 원래 저장소 기준이다. 예를 들면 `evals/local-model/...`, `evals/github-timeline-state-change-2026-09-11/...`이다.
- 학습 데이터와 GPT 결과가 없어서 이 브랜치만으로 스크립트를 다시 돌릴 수는 없다.

## 공개하지 않은 것

- **학습 데이터:** 다른 사람의 GitHub 이슈 원문·아이디와 GPT 라벨이 들어 있다.
- **LoRA 어댑터 11개:** 각 40.5MB이고, 위 데이터로 학습했다.
- 저장소가 공개라서 둘 다 올리지 않고 sha256만 `evidence/SHA256SUMS.txt`에 남겼다. 로컬 파일과 `shasum -a 256 <파일>`로 대조할 수 있다.
- 앱(web/)에 붙여 본 실험 코드도 운영 코드를 바꾸지 않으려고 뺐다.
