# 이력서 분석과 경험 지도

2026-11-11 기준 로컬 웹 구현이다. 운영 배포와 외부 모델 실호출 비교는 별개다.

## 처리 흐름

1. PDF 또는 텍스트에서 읽은 한 사람의 이력서를 사용자가 확인한다.
2. 웹 서버가 인증과 프로필 버전을 확인하고 DB에서 쓰기 권한을 선점한다.
3. 기술 분석은 이 컴퓨터의 Qwen3 4B와 기존 LoRA v6로 실행한다. 기술 후보와 원문 위치는 코드가 찾고, 모델은 전체 문맥에서 각 후보의 경험 상태를 판단한다.
4. 기술 목록, 원문, 모델 정보와 검토 수정 이력을 계정의 프로필 버전에 저장한다. 기존 JSON 저장 구조를 사용하므로 새 DB 마이그레이션은 없다.
5. 사용자가 분석 폼에서 선택한 제공자에게 이력서 본문을 보내는 데 동의하면, 같은 요청에서 각 모델이 100자 이내의 한 문장 소개를 만든다. 소개는 경험에 드러난 문제 해결과 협업 행동을 요약하고, 기술 목록과 함께 표시한다.
6. 원문 인용을 확인한 뒤 기술 결과와 생성에 성공한 소개를 한 프로필 버전에 저장한다. 한 모델이 실패해도 나머지 결과를 볼 수 있다.
7. D3 그래프는 저장된 분석, 명시적인 프로젝트 제목, 포트폴리오와 유효한 경험 기록을 연결한다. 제목을 인식하지 못한 이력서에서도 기술과 나의 연결은 표시한다.

Abstractive는 원문의 의미를 재구성하는 요약 방식이다. 외부 API를 사용해야만 가능한 방식은 아니다. 이 구현은 역할 분리를 위해 기존 로컬 분류기와 외부 생성 모델을 함께 사용한다.

## 모델과 한계

- 로컬 기술 분석: Qwen3 4B, `resume-reviewed-20261107-selected` 어댑터, `focused-state-v1` 출력.
- 새 학습은 실행하지 않았다. 검토 중이던 `activity-evidence-v2` 형식으로 재학습한 모델도 아니다.
- 최대 12,000 Unicode 코드포인트, 64개 기술 후보, 모델 입력 8,192토큰이다. 길이를 넘으면 자동 절단하지 않고 거부한다.
- 기술 사전에 없는 기술은 누락될 수 있고, 사용과 학습, 계획 등의 분류 오류가 남아 있다. 원문을 펼쳐 분류를 직접 고칠 수 있다. 사람의 수정임을 표시하며 모델 재호출 없이 저장한다.
- 현재 추천용 역량 사전은 기술 사전보다 좁다. pandas 등은 기술 목록과 그래프에 보존되지만 독립적인 추천 역량 ID가 없는 항목도 있다.
- 그래프의 프로젝트와 기술 연결은 원문에서 함께 등장했다는 의미다. 프로젝트별 실제 사용 여부를 별도로 검증한 결과가 아니다. 노드 크기도 숙련도 점수가 아닌 연결 수다.

## 외부 요약 비교

이 브랜치는 세 모델을 비교하는 로컬 실험용이다. 이미 사용하는 프로젝트 DB와 별도로 실험할 수 있다. 저장된 개인 이력서나 키 없이 시작하며, 실험할 때는 개인정보를 뺀 같은 입력을 사용한다.

| 제공자 | 초기 모델 | 비교 목적 |
| --- | --- | --- |
| OpenAI | gpt-6-luna | 간결한 요약의 비용과 사실 보존 확인 |
| Anthropic | claude-haiku-5-5 | 한국어 문장과 경험 연결 방식 비교 |
| Google | gemini-3.8-flash | 응답 시간과 긴 문맥 요약 비교 |

이는 실측 우승 모델 선정이 아닌 비교 후보다. 품질을 더 확인할 때는 Claude Sonnet 5.5 또는 OpenAI GPT-6.1 Terra로 모델 환경변수를 바꿔 시험할 수 있다.

공식 모델 목록: [OpenAI](https://developers.openai.com/api/docs/models), [Anthropic](https://platform.claude.com/docs/en/models/overview), [Gemini](https://aistudio.google.com/docs/models/gemini-3.8-flash).

`web/.env.local`에 `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`를 설정한다. 키가 없는 제공자는 비활성화된다. 값은 Git에 포함하지 않는다. 모델 ID는 `.env.example`의 `CAREERFLOW_INTRO_*_MODEL`로 변경한다.

### 비교만 빠르게 실행하기

로컬 모델 없이도 외부 요약을 비교할 수 있다. `web` 폴더에서 의존성을 설치하고 실험 DB를 준비한 뒤 서버를 켠다.

```sh
npm ci
env DATABASE_URL= DATABASE_PATH=.data/llm-api-comparison npm run db:migrate
env DATABASE_URL= DATABASE_PATH=.data/llm-api-comparison AUTH_DEV_HEADERS=1 CAREERFLOW_AI_PROVIDER=unavailable npm run dev -- --webpack --port 3323
```

별도 터미널의 `web` 폴더에서 아래 명령을 실행한다.

```sh
node scripts/dev-as.mjs 3324 llm-api-comparison 비교실험 3323
```

[이력서와 소개](http://127.0.0.1:3324/app?tab=profile)에서 기본 근거 추출과 비교할 모델을 선택하고 본문 전송에 동의한 뒤 한 번 제출한다. 전체 흐름에서 로컬 LoRA도 쓰려면 아래 로컬 실행 절차에 따라 추론 서버를 켠다. 요약 호출은 각 계정의 유효한 크레딧이나 무료 한도를 확인한 뒤 실행한다.

선택한 모델은 모두 같은 이력서 본문과 평가 지시를 받는다. 각 소개가 사실을 보존하는지, 구체적인 행동을 담는지, 한국어 한 문장으로 자연스러운지 확인한다. 결과에는 모델별 문장, 근거, 응답 시간, API가 반환한 입력 및 출력 토큰을 표시한다. 원하는 문장을 프로필 소개로 선택할 수 있다. 같은 원문, 프롬프트 버전, 제공자와 모델의 결과는 재사용한다. 모델을 바꾸면 해당 제공자의 결과를 새로 만든다.

프로필 쓰기를 모델 호출 전에 선점하므로 동시에 들어온 요청 중 하나만 생성한다. 하루 AI 한도는 10회다. 새로 소개를 생성하는 모델 수만큼 차감하며, 기술 분석만 요청하면 1회 차감한다. 외부 모델의 저장된 결과를 재사용할 때는 해당 모델의 추가 호출과 차감이 없다.

## 로컬 실행

이 Mac에서는 기존 로컬 모델, 가상환경과 어댑터를 링크해 사용한다. 다른 컴퓨터에서는 해당 파일을 별도로 준비해야 한다. 가중치와 개인 학습 자료는 Git에 올리지 않는다.

웹 폴더에서 최초 한 번 인증 파일을 만든다. 이미 있으면 덮어쓰지 않는다.

```sh
node -e 'const f=require("node:fs");f.mkdirSync(".data",{recursive:true});if(!f.existsSync(".data/lora-token"))f.writeFileSync(".data/lora-token",require("node:crypto").randomBytes(48).toString("hex"),{mode:384})'
```

`web/.env.local`에 `.env.example`에서 주석으로 표시한 로컬 연결 설정 네 줄을 복사해 주석 기호를 지운다. 아래 명령은 각각 해당 폴더의 별도 터미널에서 실행한다.

```sh
# local-llm 폴더
.venv/bin/python scripts/serve_web.py --token-file ../web/.data/lora-token
```

```sh
# web 폴더, 최초 DB 준비 시 서버를 끈 상태에서 실행
env -u DATABASE_URL DATABASE_PATH=.data/website-demo npm run db:migrate

# web 폴더
env -u DATABASE_URL DATABASE_PATH=.data/website-demo AUTH_DEV_HEADERS=1 npm run dev -- --webpack --port 3286
```

```sh
# web 폴더
node scripts/dev-as.mjs 3287 website-demo 시연계정 3286
```

접속: `http://127.0.0.1:3287/app?tab=profile`, 경험 지도: `http://127.0.0.1:3287/app?tab=graph`.

로컬 모델 서버는 `127.0.0.1`에만 열고 인증 토큰과 Host를 확인하며 브라우저 Origin을 거부한다. MLX 로딩과 추론은 같은 스레드에서 수행한다. 개인 원문과 API 응답 및 키를 로그로 남기지 않는다. Vercel에서 이 Mac의 루프백 서버를 직접 호출할 수 없으므로 운영에는 별도의 인증된 추론 서버 구성이 필요하다.

## 점수와 등급 제안

마이페이지 상단의 점수, 등급, 상위 퍼센트는 프로젝트의 현재 프로필 산정식을 따른다. 아래 100점 구성은 별도의 설계 제안이다.

제안하는 100점 구성은 결과물 완성도 40점, 본인 기여 25점, 협업 20점, 지속적인 성장 15점이다. 완료 프로젝트 개수는 결과물 항목 안에서 상한과 체감 가산을 적용한다. 단순히 프로젝트를 많이 만들거나 체크인 버튼을 누르는 것만으로 점수가 올라가지 않도록 한다.

- 결과물: 완료 프로젝트의 실제 산출물, 재현 가능한 실행과 검증 기록.
- 본인 기여: 본인 담당 과제의 완료와 근거, 변경 이력. 전체 팀의 커밋 수를 개인 점수로 쓰지 않는다.
- 협업: 여러 프로젝트에서 받은 동료평가. 적은 평가 수에는 보정을 적용하고 동일 집단의 반복 상호평가를 감시한다.
- 성장: 최근 90일의 주간 회고, 보완한 역량, 결과물에 대한 이해 확인. 접속 시간은 평가하지 않는다.

등급은 탐색, 실행, 기여, 숙련 등의 단계로 시작하고 초기 분포를 보고 경계값을 조정한다. 이력서에 적힌 기술 개수와 AI가 추정한 성격은 점수에 넣지 않는다. 솔로 활동자는 동료평가가 없다는 이유로 불이익을 받지 않도록 별도 활동군에서 집계한다.

상위 퍼센트는 같은 활동 방식과 기간의 충분한 비교 집단이 생긴 뒤 표시한다. 초기 기준 예시는 최근 90일 활동자 중 검증 가능한 완료 기록을 가진 50명 이상이다. 집단 크기, 기준일과 동점 처리 방식을 함께 공개하며, 데이터가 적으면 집계 중으로 표시한다. 이 퍼센트는 사이트 내 활동 지표이며 전체 개발자의 실력 순위가 아니다.
