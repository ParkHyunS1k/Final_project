# 공개 프로필과 자랑 카드 설계 · 2026-11-17

## 왜

사용자가 7일 스프린트에서 얻은 등급·뱃지·완주 기록을 인스타·블로그에 **자랑**하게 한다(사용자 결정 2026-11-17). 공유된 카드가 서비스를 알리는 효과도 노린다. 순위표(다른 사람 목록)는 만들지 않는다. 자랑의 단위는 "한 사람의 프로필"이다.

## 목표

- 마이페이지의 **'내 프로필 공유'** 하나로 요약 카드 이미지와 공개 프로필 링크를 만든다.
- 링크를 블로그·SNS에 붙이면 요약 카드가 미리보기로 뜨고, 누르면 그 사람의 **공개 프로필 페이지**로 간다.
- 등급과 상위 %는 **내부 산정식 하나**로 정한다. 산정식은 나중에 구체화하므로(사용자 예정) 한 곳에서 버전을 붙여 바꿀 수 있게 둔다.
- 동료평가 결과가 공개되는 화면에 "프로필에 반영됐어요 · 프로필 공유하기" 링크를 둔다(별도 결과 카드는 만들지 않는다).

## 하지 않는 것

- 다른 사람 목록을 보여 주는 순위표·리그.
- 프로젝트별 결과 카드 여러 종류(시안 A·B·C 중 하나로 통일).
- 팀원의 이름·점수·개별 평가 노출. 공개 프로필은 본인 결과만 담는다.
- 실제 SNS 자동 게시. 사용자는 이미지를 저장하거나 링크를 복사해 직접 올린다.

## 실패로 보는 것

- 본인이 켜지 않았는데 프로필이 열리거나, 끈 뒤에도 링크·미리보기 이미지가 계속 보인다.
- 카드나 프로필에 팀원의 이름·점수·평가가 나온다.
- 평가를 내지 않아 결과가 가려진 프로젝트의 점수, 아직 공개 전인 점수가 산정식에 들어간다.
- 마이페이지·카드·프로필의 등급이나 상위 %가 서로 다르게 나온다.

## 바뀌는 기존 원칙 (CLAUDE.md·docs 갱신 필요)

- "공유 링크는 없다" → 본인이 켠 공개 프로필 링크가 있다.
- "점수는 본인 결과만 돌려준다" → 본인이 켠 공개 프로필에서는 그 사람의 프로필 점수·등급·상위 %·뱃지·완주 프로젝트·확인한 업무를 누구나 본다. 다른 사람의 점수는 여전히 아무 화면에도 나오지 않는다(상위 %는 숫자 하나로만).
- 마이페이지 요약의 '최고 등급'(프로젝트 중 최고) → '프로필 등급'(산정식 점수로 정한 등급). v1에서는 평균 기반이라 일부 사용자의 표시 등급이 내려갈 수 있다(사용자 동의 2026-11-17).

## 점수·등급·상위 %

### 프로필 점수 (산정식)

- `lib/profile-score.ts`의 함수 하나가 계산한다: 입력은 한 사용자의 사실(프로젝트별 공개된 내 동료평가 점수, 완주·참여 중단, 학습한 날 등), 출력은 `{ score: number | null, formulaVersion: string }`.
- **v1 = 지금 마이페이지 '동료평가 평균'과 같다**: 공개됐고 가려지지 않은(`resultHidden`이 아님) 프로젝트별 내 점수의 평균, 소수 첫째 자리 반올림. 그런 프로젝트가 없으면 `null`. 참여 중단한 프로젝트는 점수가 없으므로 자연히 빠진다.
- 산정식을 바꿀 때는 이 함수와 버전 문자열만 바꾼다. 화면·카드·상위 %는 이 결과만 쓴다.

### 등급

- 프로필 점수에 기존 등급 하한을 그대로 쓴다(`gradeOf`: 4.8↑ S, 4.0↑ A, 3.0↑ B, 2.0↑ C, 그 아래 D). 점수가 없으면 **E**.
- 프로젝트별 결과 화면의 등급(그 프로젝트의 내 점수)은 그대로 둔다.

### 상위 %

- 비교 대상: 저장된 프로필 점수가 있는(점수 `null` 아님) **모든 사용자**. 최근 활동 여부로 거르지 않는다.
- 내 순위 = (나보다 점수가 높은 사람 수) + 1, 같은 점수는 같은 순위. 상위 % = `max(1, ceil((순위 − 1) / 전체 × 100))`, 1~100의 정수. 1등은 인원과 상관없이 "상위 1%", 100명 중 13등은 "상위 12%", 2명 중 2등은 "상위 50%".
- **최소 인원 없이** 모든 사용자에게 마이페이지에서 보인다(사용자 결정 2026-11-17). 공개 프로필·카드도 같은 숫자를 쓴다. 점수가 없으면 "평가를 받으면 상위 %가 나와요".
- 다른 사람의 점수는 내보내지 않는다. 응답에는 내 상위 %와(필요하면) 전체 인원만 담는다.

### 저장과 갱신 (하루 한 번 일괄, 사용자 결정 2026-11-17)

- 표 `profile_scores(user_id PK, score numeric NULL, grade text, formula_version text, computed_at timestamptz)`.
- **매일 한국 시간 03:00**에 Vercel Cron이 내부 경로를 불러 프로젝트 멤버였던 적이 있는 **모든 사용자**의 프로필 점수·등급을 다시 계산해 덮어쓴다. 서버 비밀값(`CRON_SECRET`)으로만 실행한다. Vercel Cron은 운영(main) 배포에서만 돈다.
- 마이페이지·공개 프로필·카드의 **프로필 등급·점수·상위 %는 모두 이 저장값**을 쓴다. 그래서 세 곳이 항상 같고, "11월 17일 03:00 기준"처럼 계산 시각을 함께 보인다.
- 저장값이 아직 없는 사용자(가입 직후 등)는 "매일 새벽에 계산돼요"를 보인다. 프로젝트별 결과 화면의 등급(그 프로젝트의 내 점수)은 지금처럼 바로 보인다.
- 산정식 버전이 바뀌면 다른 버전의 저장값은 비교에서 뺀다(같은 버전끼리만 순위). 버전을 바꾼 날은 다음 일괄 계산 뒤에 새 값이 보인다.

## 공개 프로필

### 설정 (마이페이지 '설정' 탭 아래 '공개 프로필' 카드)

- **공개 켜기/끄기** — 기본 꺼짐. 끄면 링크·미리보기 이미지가 즉시 404(캐시하지 않는다).
- **아이디** — `/u/<아이디>`. 소문자 영문·숫자·`-`·`_`, 3~20자, 중복 불가, 예약어(`app`, `api`, `admin`, `u`, `new`, `settings` 등) 불가. 바꾸면 예전 주소는 바로 없어진다(제 판단: 리다이렉트는 두지 않는다).
- **프로필 이름** — 기본값은 Google 계정 이름, 바꿀 수 있다(1~30자).
- **GitHub 아이디 보이기** — 기본 꺼짐. 연결된 계정이 있을 때만 켤 수 있다.
- **항목 숨기기** — 프로젝트·업무마다 공개 프로필에서 뺄 수 있다.
- **완료 근거 보이기** — 업무마다 기본 숨김, 켜면 근거 원문을 보인다.
- 모든 변경은 서버에서 본인만, 버전으로 동시 변경을 막는다.

표 `public_profiles(user_id PK, handle text UNIQUE, display_name text, enabled bool DEFAULT false, show_github bool DEFAULT false, hidden_projects jsonb, hidden_experiences jsonb, shown_evidence jsonb, version int, updated_at)`. RLS ON(정책 없음), 서버만 접근. 변경 기록은 기존 관례대로 남긴다.

### 페이지 `/u/<아이디>` (로그인 없이 누구나)

1. **요약** — 프로필 이름, 목표 직무, 프로필 등급(큰 글자), 프로필 점수(5점), 상위 %, 완주 수, 연속 학습. (켰으면) GitHub 아이디.
2. **뱃지** — 받은 뱃지와 횟수(마이페이지 활동 탭과 같은 값).
3. **학습한 날** — 최근 12주 칸.
4. **완주한 프로젝트** — 이름, 기간, 팀 인원("3인 팀"), 내 역할(팀장/팀원/솔로), 그 프로젝트의 내 등급. 참여 중단한 프로젝트는 빠진다. 진행 중 프로젝트는 넣지 않는다(제 판단).
5. **내가 한 업무** — '본인 확인'된 경험만(재확인 필요는 자동 제외): 이력서 문장, 역량 태그, (켰으면) 완료 근거.
6. 아래에 서비스 소개 링크("나도 7일 스프린트 시작하기").

공개 프로필의 숫자는 마이페이지와 같은 함수로 계산한다. 비공개면 404이며 "비공개 프로필"이라고도 알리지 않는다(존재 여부를 숨긴다).

## 카드 이미지

- 디자인: 시안 **A(등급 포디움)** 기반에 C의 결승선 체크무늬와 완주 수를 더한다(사용자 결정 2026-11-17). 큰 등급 글자, "프로필 점수 4.5 · 상위 12%", 완주 수·연속 학습, 뱃지 몇 개, 로고와 `…/u/<아이디>`.
- 두 크기: **스토리 1080×1920**(이미지 저장용), **링크 미리보기 1200×630**(블로그·SNS가 자동으로 가져가는 OG 이미지).
- `next/og`의 `ImageResponse`로 서버에서 만든다(`app/u/[handle]/opengraph-image`와 스토리용 라우트). 제약: flexbox만, 번들 500KB 이하, 글꼴은 ttf/otf/woff — 한글 글꼴은 카드에 쓰는 글자만 담은 부분 글꼴을 쓰거나 실행 시 불러온다(구현 때 확인).
- 공개가 꺼져 있으면 이미지도 404.

## 화면 흐름

- **마이페이지 요약 카드**: '최고 등급' → '프로필 등급', 옆에 상위 %. '내 프로필 공유' 버튼.
  - 공개가 꺼져 있으면 버튼이 공개 프로필 설정(아이디 정하기·켜기)으로 안내한다.
  - 켜져 있으면 공유 시트: 카드 미리보기, '이미지 저장'(스토리 크기 PNG), '링크 복사', '프로필 보기'.
- **동료평가 결과 공개 화면**(끝난 프로젝트 홈): "프로필에 반영됐어요 · 프로필 공유하기" 링크 → 마이페이지 공유 시트(주소로 바로 열 수 있게).

## 검증할 것

- 일괄 계산: 비밀값 없이 부르면 401, 모든 멤버의 저장값이 같은 버전으로 갱신, 결과가 가려진 사용자는 점수 없음.
- 공개 끔/켬/아이디 변경 직후 `/u/…`와 이미지가 바로 바뀐다(404 포함).
- 공개 프로필 HTML·이미지에 팀원 이름·점수가 없다.
- 결과가 가려진 프로젝트, 공개 전 점수, 참여 중단 프로젝트가 점수에 들어가지 않는다.
- 상위 %: 같은 점수 동률(같은 %), 혼자일 때 "상위 1%", 점수 없는 사람은 비교 대상에서 빠짐, 산정식 버전이 다른 저장값 제외.
- 아이디 중복·예약어·형식 위반 거절, 동시 변경 버전 충돌.
- 마이페이지·프로필·카드의 등급·상위 %가 같다.

## 빌더에게 맡기는 것

- 화면 세부 배치, 공유 시트 구현(`navigator.share`가 있으면 쓰고 없으면 저장·복사), 한글 글꼴 처리 방식, 변경 기록 표의 형태, 예약어 목록.

## 제가 정한 것 (확인 부탁)

- 아이디를 바꾸면 예전 주소는 리다이렉트 없이 없어진다.
- 진행 중 프로젝트는 공개 프로필에 넣지 않는다.
- 비공개 프로필은 404로만 응답한다.
